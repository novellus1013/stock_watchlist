## 1. 실행 방법

[공공데이터포털](https://www.data.go.kr)에서 *금융위원회_주식시세정보*를 활용신청하면
자동 승인됩니다. 인증키는 마이페이지 → 데이터활용 → Open API → 인증키 발급 현황에서
확인할 수 있습니다.

<img width="989" height="203" alt="인증키 현황" src="https://github.com/user-attachments/assets/e5445730-64bc-452e-ba6f-5774199f59aa" />


```bash
cp env.example.json env.json     # env.json에 개인키 입력
flutter pub get
flutter run --dart-define-from-file=env.json  # 시뮬레이터 실행 후 command 입력
```

키가 없어도 빌드는 성공하고 안내 화면이 뜹니다. 테스트는 저장해둔 응답을 쓰기 때문에
키 없이 `flutter test`로 돌아갑니다.

**사용한 엔드포인트**

```
https://apis.data.go.kr/1160100/service/GetStockSecuritiesInfoService/getStockPriceInfo
```

## 4. 검색 알고리즘과 자료구조

### 서버 검색을 쓰지 않은 이유

이 API도 부분 문자열 검색을 지원합니다. `성전`으로 4건이 나옵니다.
그런데도 로컬에서 처리했습니다.

| 근거 | 실측 |
|---|---|
| 초성 검색이 안 됨 | 초성으로 질의하면 0건 |
| 정렬 순서를 정할 수 없음 | 완전일치 우선, 시가총액 순 정렬을 서버에 요구할 방법이 없음 |
| 한 번에 전부 받아짐 | 2,872건 / 766KB / 0.62초 |
| 응답 시간이 들쭉날쭉함 | 0.06~16.3초 (문서 명세는 500ms) |

### 자료구조

| 구조 | 담당 |
|---|---|
| 종목 리스트 | 원본. 색인에는 정수 위치만 담음 |
| 코드 → 위치 맵 | 종목코드 완전일치를 O(1)로 |
| **bigram → 위치 리스트** | 종목명 중간 일치 |

Trie는 접두사만 찾을 수 있어서 "종목명 중간에 포함" 요건을 못 채웁니다.
trigram은 가장 짧은 종목명이 2자(두산, CJ)라 그런 종목이 색인에 못 들어갑니다.

### 검색 처리

```
빈 질의   → 전체
숫자      → 코드 완전일치 + 부분일치, 0건이면 이름 검색 폴백
1글자     → 선형 (색인 키가 2글자부터)
2글자~    → bigram 분해 → 위치 리스트 교집합 → 원문 재검증
```

교집합은 짧은 리스트부터 처리합니다. 가장 긴 게 `에스` 131건이고 평균은 2.52건입니다.
bigram만으로는 후보가 좁혀질 뿐이라 마지막에 원래 이름으로 한 번 더 확인합니다.

종목명은 공백과 `&`, 하이픈, 마침표, 괄호를 지우고 소문자로 바꿔 색인에 넣습니다.
`KT&G`는 `ktg`, `S-Oil`은 `soil`, `CJ4우(전환)`은 `cj4우전환`이 됩니다.
2,872건에 적용했을 때 이름이 겹치는 경우는 없었습니다.

결과는 완전일치, 접두사, 부분일치 순으로 정렬하고 같으면 시가총액이 큰 쪽을 앞에 둡니다.

시장 구분은 색인을 두지 않고 검색 결과를 걸러냅니다. 값이 코스피 943건, 코스닥
1,821건, 코넥스 108건 세 가지뿐이라 색인을 만들어도 후보가 크게 안 줄어듭니다.

### 복잡도와 실측

선형 탐색은 종목 수에 비례해 느려지고, 색인은 가장 짧은 위치 리스트 길이를 따라갑니다.
공간은 종목명 길이의 합에 비례합니다. 2,872 × (평균 4.88자 − 1) ≈ 11,140을 예상했고
실제로 11,077이 나왔습니다.

```
질의        결과   선형(μs)  색인(μs)     2,872건 · 2,000회
─────────────────────────────────     색인 구축 17ms
성전           4      321.4       0.4     포스팅 11,077
삼성          26      319.1       0.7     고유 bigram 4,396
홀딩스        81      350.9       3.2
에스         131      321.0       3.3
─────────────────────────────────
평균                  326.1      1.44
```

선형은 결과가 몇 건이든 시간이 거의 같고, 색인은 리스트 길이를 따라가서 4건짜리와
131건짜리가 8배 차이납니다. 전체 배율은 실행할 때마다 67~115배로 흔들려서 하나로
못 박지 않았습니다. `flutter test test/benchmark_test.dart`로 다시 잴 수 있습니다.

## 5. 예외 처리

### 실패와 부재를 나눈 기준

요청이 실패한 것과 데이터가 없는 것은 사용자가 할 일이 다릅니다. 앞은 다시 시도하면
되고 뒤는 날짜를 바꿔야 해서 둘을 나눴습니다. 응답이 성공인데 0건인 경우는 에러로
묶지 않았습니다.

| 순서 | 부재 사유 | 판단 근거 |
|---|---|---|
| 1 | 상장폐지, 거래정지 | 최신 데이터에 종목코드 없음 |
| 2 | 거래일 아님 | 거래일 달력에 없는 날짜 |
| 3 | 확인 불가 | 달력 조회 범위 밖 |
| 4 | 상장 이전 | 과거 1년 조회가 0건 |

한 종목에 사유가 둘 다 해당할 수 있습니다. 폐지된 종목의 휴장일이 그렇습니다.
그래서 **날짜를 바꿔도 결론이 안 바뀌는 것부터** 봅니다. 관심종목 목록에서도
지우지 않고 사유를 같이 보여줍니다.

### 거래일 달력

KRX 휴장일은 법정공휴일과 다릅니다. 근로자의 날은 공휴일이 아닌데 쉬고, 제헌절은
2026년부터 공휴일로 다시 지정되면서 쉬었습니다. 이런 규정이 해마다 바뀌기 때문에
기준 종목 하나의 거래일 목록을 받아서 달력으로 씁니다.

### 응답과 파싱

응답이 JSON, XML, 평문(`Unauthorized`) 세 가지로 옵니다. 에러 코드는 사용자가 할 일이
달라지는 경우만 나눠서 세 가지 문구로 묶었습니다. 값은 15개 필드가 전부 문자열이고
소수점 앞의 0이 빠져서 오기 때문에(`.25`, `-.28`) 그대로 화면에 쓰면 `.25%`가 됩니다.

### 깜빡임과 순서 역전

날짜를 바꿔도 화면이 비지 않고 진행바만 뜹니다. 두 번째 요청을 일부러 12초 늦춰서
나중 요청이 먼저 끝나게 만들어봤는데, 늦게 도착한 응답이 화면을 덮지 않아서 따로
처리하지 않았습니다.

## 6. 프로젝트 구조

**MVVM + Repository.** Flutter 공식 가이드가 권장하는 구조입니다. 화면이 데이터를
어디서 가져오는지 모르게 하려고 나눴습니다. 실제로 관심종목은 로컬 저장소에서,
시세는 API에서 오는데 화면 코드는 둘을 구분하지 않습니다.

**feature-first.** 화면 하나를 고칠 때 열어야 할 폴더가 하나로 끝납니다. 계층으로
먼저 자르면 관심종목 하나를 바꾸는 데도 model, repo, view 세 군데를 오가야 합니다.

```
lib/
├── core/                인프라 (환경변수 · 파싱 · 예외 · API 클라이언트)
└── features/
    ├── market/          종목·시세·거래일 — 세 화면이 공유
    ├── search/          index/ ★ 순수 Dart 검색 모듈
    ├── watchlist/
    └── detail/
```

## 7. 테스트

```bash
flutter test        # 27 tests
```

대조합니다. 저장해둔 응답을 쓰기 때문에 네트워크 없이도 매번 같은 결과가 나옵니다.

검색과 파싱 로직 108줄은 라인 커버리지 100%입니다.

## 8. 아쉬운 점

**초성 검색.** 로컬 검색을 택한 근거 중 하나였는데 정작 넣지 못했습니다.
색인을 만들 때 종목명을 초성으로 바꿔 넣기만 하면 지금 구조 그대로 됩니다.

**화면 테스트 작성.** 5장에서 손으로 확인한 것들(날짜를 바꿔도 화면이 비지 않는지,
사유가 순서대로 나오는지)은 테스트로 고정해두는 게 맞습니다. 지금은 검색과 파싱
로직에만 테스트가 있습니다.

**거래정지 판단.** 1년 넘게 거래가 멈춘 종목을 "상장 이전"으로 잘못 판단합니다.
이 API에 상장일 항목이 없어서, 구분하려면 그 종목의 첫 거래일을 따로 찾아야 합니다.

## 9. AI 도구 활용

Claude와 Context7으로 Riverpod 3.0, freezed 3.x 등 최신 버전 문서를 대조하며
라이브러리 버전을 맞췄습니다. 설계 초기에는 API 응답 스냅샷을 확보해 테스트에
활용하기 위해 curl과 jq 기반 검증에 썼고, 설계 대안을 비교하고 장단점을 정리하는
데에도 활용했습니다.

다만 색인 통계, 검색 속도, API 응답 형태, 거래일 목록은 전부 직접 측정해서
확인했습니다. 설계 단계에서 잡아둔 숫자가 구현 후 측정값과 달라서
(bigram 11,088 → 11,077, 최대 131건) 측정값으로 바꿨습니다.
